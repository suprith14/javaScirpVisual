Reference: how the engine runs your code

Suggested workflow. Read the lesson → predict the output → step through the execution and read each explanation → click lines you don't understand → solve the matching challenge without looking at the solution.
Creation phase. Before running anything, the engine scans the code and allocates every declaration (hoisting): var → undefined, function → the whole function, let/const/class → uninitialized (Temporal Dead Zone).
Execution phase. Statements run top to bottom and values are assigned.
Call stack. Each call creates an execution context (its own variable environment, this and scope chain). It is pushed on call and popped on return.
Scope chain and closures. Name lookup walks outward through the scopes where a function was defined. A function keeps those scopes alive after the outer function returns.
Heap and garbage collection. Objects live in the heap; variables hold references. GC view shows the root that keeps each object reachable; unreachable objects are collected (mark-and-sweep).
Web APIs, queues, event loop. Timers, fetch and DOM events are handled by the host. Their callbacks enter the callback queue; the event loop runs one task when the stack is empty, then drains the microtask queue (promise reactions, await continuations).
Paused functions. async functions at await, generators at yield and modules at top-level await leave the stack and keep their state.
Simulated host. fetch routes: /api/users, /api/users/1–3, /api/todos, /api/slow, /api/error; add your own with mockFetch(url, data, { status, delay }). Page elements #title #btn #name #output; simulateClick(sel, ms), simulateTyping(sel, text, ms). Split code into modules with // @file name.js lines.
More environments. Start the code with // @env node to run it as Node.js (process.nextTick, setImmediate, event-loop phases, require("events"), require("util")). Add a file whose name contains "worker" (e.g. // @file worker.js) and start it with new Worker("worker.js") to use a Web Worker. Turn on Internals in the Heap to see simulated hidden classes, inline caches and hot functions.
Real browser features. fetch("https://…") requests the real internet: the app fetches each URL once, then replays the program with the real response and timing (servers must allow cross-site requests, known as CORS). alert/confirm/prompt show real dialogs, and your answers are replayed. localStorage is kept between runs. Add a // @file index.html section to write your own page; click or type in the Page preview and the program re-runs with your event.
Step limit. Higher limits allow longer programs but use more memory.
